# Reference Source Notes

Each reference screen from the GitHub repository `NielHitesh001/App_prototype_02` has been audited against the product brief and the approved product decisions. No raw code or markup is copied directly; all views are re-implemented with accessible, clean React components and strict TypeScript.

| Repo Folder | Target Route / Feature | Original Content in HTML Export | Differences & Adjustments for MVP |
|---|---|---|---|
| `home_discover_cypriot_hearth_radar` | `/discover` | Uses "Kalihora", delivery categories, hardcoded "57 Tavernas", static filter buttons. | Rebranded to **Troo**. Replaced hardcoded venue counts with live derived counts from filtered data. Uses terracotta & cream tokens. |
| `home_discover_cypriot_hearth_radar_interactive` | `/discover` (Map view) | Contains simulated canvas/SVG animated radar ping with fake timer countdown. | Replaced with an accessible, static map card featuring an explicit "Open map" button. Animated loop is removed to adhere to `prefers-reduced-motion`. |
| `home_discover_reservation_modal_open` | `/discover`, `/taste`, `/events` (Shared Booking Sheet) | Multi-step modal claiming "0% booking fee", unvalidated party sizes, hardcoded time chips. | Rebuilt as an accessible, focus-trapped dialog (`role="dialog"`). Features a 1–4 guest stepper, strict balance checking guard (`canBook()`), live wallet debit, and transaction logging. |
| `kouzina_cultural_taste_unified_dining` | `/taste` & `/kouzina` | Combines food delivery with cultural heritage stories; "Order" buttons without shopping cart or checkout flow; mentions "Kalihora Pass". | Split into two clean destinations: `/taste` (editorial storytelling, artisan spotlights, reservable signature dishes) and `/kouzina` (dedicated delivery view with search, cards with delivery fee/min order, cart drawer, and checkout). |
| `cypriot_hearth_living` | Design Reference | `DESIGN.md` defining typography (Plus Jakarta Sans) and palette (terracotta `#9A4A3A`, cream `#FBF5EE`, text `#2B2118`). | Primary design token reference for the app's Tailwind color palette and typography hierarchy. |
| `warm_mediterranean_hearth` | Design Reference | `DESIGN.md` defining Outfit & Inter font pairing and warm earthen tones. | Supplementary design token reference for card spacing, pill radius, and ambient elevation. |
| `pass_wallet_my_pass_1` | `/pass` | Shows "Tap to Pay" via NFC button, QR code modal, and hardcoded user pass. | NFC replaced with an accessible Web QR code modal. Pass view prompts sign-in when no session exists, rather than displaying fabricated user identities. |
| `pass_wallet_my_pass_2` | `/pass` & `/pass/ledger` | Tabbed pass view with claims of "Cryptographically signed ledger" and "Limassol Tourism Guild funding". | Removed unverified claims. Implemented tablist (`role="tablist"` with `aria-selected`) connecting to real ledger records. |
| `pass_wallet_tonight_s_table_details` | `/pass` (Active booking detail) | Active booking ticket for To Patriko (Table 4, Hearthside, 20:15, dietary sync). | Integrated as a real dynamic component in the user's Pass view when active bookings exist. |
| `to_patriko_taverna_post_dining_settlement_receipt` | `/pass/ledger/:id` | Itemized bill claiming "Platform commission: €0.00 (Zero commission partner network)". | Commission claims removed. Formatted as a clean subpage receipt derived from actual ledger entries with reference, date, amount, and payment mode. |
| `winter_events_curated_hearthside_experiences` | `/events` | Event cards with hardcoded weekday strings (e.g. "Friday"), hardcoded discount calculations, and "Verified host" badge. | All dates and weekdays derived dynamically in `Europe/Nicosia` using `Intl.DateTimeFormat`. Badges displayed only when `verified: true`. Shared booking sheet integration. |
| `to_patriko_taverna_partner_shift_dashboard_dietary_synced` | `/partner` | Staff shift dashboard with live cover counts, revenue, and fireplace toggle. | **Phase 2 Feature.** MVP implements a partner landing page with an inquiry form and contact action. The shift dashboard is documented in `BACKLOG.md`. |
